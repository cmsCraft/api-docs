# Changelog

Notable changes to the public API and to these docs. Breaking changes are announced here before they reach
production; see the [stability policy](/schema#stability-policy).

## 2026-10-28

- **New: site settings and texts.** `publicSiteSettings` returns every setting the site declares (the editor's value,
  else the declared default), and `publicSiteTexts(locale)` the editors' overrides of the site's UI texts for one
  language. Both are JSON; saving them sends the revalidation tags `site-settings` and `site-texts`
  ([Site settings and texts](/guides/site-settings)).
- **New: client zone records.** `clientZoneRecordTypes` describes the record types a signed-in client may read, and
  `myRecords(namespace, types)` returns that client's records plus the shared ones. `myRecords` needs the client's
  access token, must never be cached, and answers `STEP_UP_REQUIRED` for sensitive types without a recent second factor.
  New types: `ClientZoneRecordType`, `CustomerRecord`, `CustomerRecordField`, `CustomerRecordFieldOptions`,
  `CustomerRecordChoice` and the enums `CustomerRecordAudience`, `CustomerRecordCardinality`, `CustomerRecordFieldRole`
  and `CustomerRecordFieldType` ([Client zone records](/guides/client-zone-records),
  [Client zone errors](/errors#client-zone-errors)).
- **New: `Customer.isTest`.** `true` for a test customer the project's staff created to try the client zone
  ([Test customers](/guides/client-zone-records#test-customers)).
- **New: `EntityType.SITE_SETTING`.**

## 2026-10-25

- **Newsletter sign-up needs e-mail confirmation.** `subscribeNewsletter` now uses double opt-in: the address gets a
  confirmation e-mail and receives newsletters only after it clicks the link (unless it was already subscribed). The
  answer no longer tells whether the address was already on the list. **Behaviour change:** `status` is always
  `PENDING`, and `PublicNewsletterSubscription.id` is `@deprecated` and always `0`. If your site reads `id` or branches
  on `status`, show one "check your inbox to confirm" message instead ([Newsletter](/guides/mutations#newsletter)).
- **New: `MainMailDtoTemplate` values** `customer_second_factor_reset` and `newsletter_confirm`.

## 2026-10-18

- **New: development tokens.** Create up to 10 per developer project in **Settings → Integrations → Development
  tokens**: one per developer, CI or staging server, each shown once and revoked on its own. A development token
  (`cmsdev_…`) is read-only (`DEV_TOKEN_READ_ONLY`, HTTP 403), for servers and `localhost` only
  (`DEV_TOKEN_SERVER_ONLY`, HTTP 403), sees unpublished content (drafts, scheduled posts, inactive products, cancelled
  slots), has its own limits (5,000 requests per day and 200 per minute per token, nothing refused during the beta) and
  is never billed. Use it in `.env.local`; the deployed site keeps the live token. **If your live token was on laptops
  or in CI, regenerate it** ([Development tokens](/auth#development-tokens)).
- **New: `PublicScheduleSlot.status`** (`SlotStatus`: `OPEN` or `CANCELLED`). The live token only ever gets `OPEN` slots;
  a development token also gets cancelled ones ([What a development token sees](/auth#what-a-development-token-sees)).
- **New: `ShopOrder.operator`.** The seller's details as at checkout (`ShopOperator`: name, IČO, DIČ, address, e-mail,
  phone), so an order page shows who the customer bought from even after the shop changes its details. Orders placed
  before this change show the shop's current operator ([Reading an order](/guides/shop#reading-an-order)).

## 2026-10-17

- **Request API access from the admin.** Open **Settings → Integrations** and use the **Request API access** card; no
  e-mail needed. Staff review the request and e-mail you the decision
  ([Authentication](/auth#getting-the-token)).
- **Deprecated: `publicOrderByNumber`** (the older order lookup by number and e-mail). Use `publicShopOrder(token)`; without
  the order link, a customer can still withdraw with `requestShopOrderWithdrawal(orderNumber, email)`. It will be removed
  after 2027-01-15.
- **Breaking, already in effect: `createPublicOrder` and its types were removed; use `createShopOrder` (e-shop
  module).** This change is live today and was not announced in advance. The removed
  types are `CreatePublicOrderInput`, `PublicOrderItemInput` and `PublicOrderResult`. `createShopOrder` is priced on
  our side, supports delivery methods (including Packeta points) and bank-transfer payment, and takes an optional
  `idempotencyKey` ([E-shop guide](/guides/shop)). The new mutation needs the e-shop module. `ModuleType.ORDERS` stays in the enum but can no longer be enabled.
- **E-shop API (beta).** New operations: `publicShop`, `publicShopOrder(token)`, `createShopOrder` and
  `requestShopOrderWithdrawal`. New product fields: `shopPriceMinor`, `vatRate`, `inStock`, `requiresShipping`,
  `options` and `optionListName`. New types include `PublicShop`, `ShopOrder`, `CreateShopOrderInput`,
  `CreateShopOrderResult` and `DeliveryMethodType`, and the enums gained `ModuleType.ESHOP` and `EntityType.SHOP`. The
  module is in beta: a project without it answers `MODULE_DISABLED`, and once it is on, a shop answers `SHOP_NOT_READY` until its setup is finished
  ([E-shop guide](/guides/shop), [Shop errors](/errors#shop-errors)).
- **Developer panel.** The admin panel has a **Developer** section under **Settings → Integrations** with the
  endpoint, the header name, the project's stage and your usage today. It sits above the **API Token** card
  ([Authentication](/auth#getting-the-token)).
- **Usage is counted, nothing is refused.** A Build developer project is counted against 5,000 requests and 100
  mutations per day, a Live one against 1,000,000 requests per month. During the beta nothing is refused when a
  number is passed ([Usage](/errors#usage)). The code `DAILY_LIMIT` is reserved and not returned.
- **Domains on developer projects.** The owner of a developer project that cms-craft does not host adds the
  frontend's domains; on a project we host, ask support ([Cache revalidation](/guides/revalidation#domains)).
- **Real error codes.** Errors now carry a specific `extensions.code`: `NOT_FOUND`, `CONFLICT`, `TOO_MANY_REQUESTS` and
  others, instead of `INTERNAL_SERVER_ERROR`. `extensions.originalError` is gone. Branch on the code
  ([Errors & limits](/errors#error-reference)).
- **HTTP 429 for rate limits.** A rate-limited request answers HTTP 429 with a `Retry-After` header and the code
  `TOO_MANY_REQUESTS` ([Rate limits](/errors#rate-limits)).
- **Suspended projects.** A request for a suspended project answers HTTP 403 with the code `PROJECT_SUSPENDED`.
- **Any origin.** `/graphql/public` now answers browser requests from any origin, without cookies or credentials. We
  still recommend calling it from your server ([Authentication](/auth#call-the-api-from-your-server)).
- **Per-token limit.** On a developer project whose site cms-craft does not host, the general 200-per-minute limit is
  counted per API token instead of per IP.
- **Token access.** The API token is shown to the owner of a developer project who has developer access. Access was
  granted by our team on request ([Authentication](/auth#getting-the-token)).
- **Token checks.** A `project-auth` value that is not 64 lowercase hex characters is refused with
  `not matched token`. A new or regenerated token can take up to 2 seconds to start working
  ([Authentication](/auth#regenerating-the-token)).

## 2026-10-16

- **Docs rewritten to match production.** Authentication is the `project-auth` header with the project's API token;
  the API is meant to be called from your server; rate limits, query limits and error shapes are documented as the
  API returns them today ([Authentication](/auth), [Errors & limits](/errors)).
- **Schema download.** The public schema is published at
  [https://docs.cms-craft.com/schema.graphql](https://docs.cms-craft.com/schema.graphql) and updated when the API
  changes, for code generators and editors ([Schema & types](/schema)).
- **Breaking-change policy.** Breaking changes are announced in this changelog; anything removed is first marked
  `@deprecated` in the schema for at least 90 days.
- **New guides:** a [Quickstart](/getting-started) with a complete Next.js and Astro starter, and
  [Cache revalidation](/guides/revalidation) describing the request cms-craft sends to your site after every save.
