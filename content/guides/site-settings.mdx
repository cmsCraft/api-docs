# Site settings and texts

A site can let the project's editors change some of its behaviour and wording in the admin panel without a deploy:
**settings** (switches and options, such as whether a section is shown) and **texts** (overrides for the site's own UI
strings, per language). The site declares which settings and texts exist, with their defaults; editors change the
values; your site reads them with two queries.

Sites built from a cms-craft template declare them already. Until a project has a declaration, both queries answer an
empty object `{}`.

## Settings

```graphql
query SiteSettings {
  publicSiteSettings
}
```

`publicSiteSettings` is a JSON object with **every declared setting**, keyed by the setting's key. Each value is the one
an editor saved, or the declared default when nothing was saved (or when the saved value no longer fits the
declaration). So you always get a full set and never need a fallback of your own:

```json
{
  "data": {
    "publicSiteSettings": {
      "showNewsletter": true,
      "heroLayout": "split",
      "openingHoursNote": "Closed on public holidays"
    }
  }
}
```

## Texts

```graphql
query SiteTexts($locale: String!) {
  publicSiteTexts(locale: $locale)
}
```

`locale` is one of the project's languages (`publicProjectInfo { availableLanguages { locale } }`, see
[Localization](/guides/localization)). The answer is a flat JSON object of dotted key to string, and it holds **only
the overrides**: your site's own messages keep the defaults, and you lay these strings over them.

```json
{
  "data": {
    "publicSiteTexts": {
      "home.hero.title": "Fresh bread every morning",
      "footer.contact.cta": "Write to us"
    }
  }
}
```

For each declared text, the answer has:

- the editor's text for `locale`, when there is one;
- otherwise nothing when the declaration has a default for `locale` (your messages already hold it);
- otherwise the editor's text for the project's main language, when there is one.

A locale the project does not have answers `{}`. A saved text that no longer fits the declaration counts as not saved.

```ts
// Your site's messages for the locale, with the editors' overrides on top.
const messagesFor = (defaults: Record<string, string>, overrides: Record<string, string>) => ({
	...defaults,
	...overrides
})
```

If your messages are nested (`{ home: { hero: { title } } }`), set each dotted key at its path instead of spreading.

## Caching

Both answers are the same for every visitor, so cache them. When an editor saves, cms-craft sends the tag
`site-settings` or `site-texts` to your site's `/api/revalidate` ([Cache revalidation](/guides/revalidation#tags)):

```ts
const { publicSiteSettings } = await cmsQuery<{ publicSiteSettings: Record<string, unknown> }>(
	'query SiteSettings { publicSiteSettings }',
	{ tags: ['site-settings'] }
)
```

`cmsQuery` is the helper from the [Quickstart](/getting-started).

## Brand

The project owner can set a logo, a site icon, an accent colour and a font pair in the admin panel (Settings → Brand).
Your site reads them from `publicProjectInfo.brand`:

```graphql
query Brand {
  publicProjectInfo {
    brand {
      logo { url width height }
      logoDark { url width height }
      icon32
      icon180
      icon192
      icon512
      accent
      fontPair
    }
  }
}
```

`brand` is always there. Each field in it is null until the owner sets it, and a brand with every field null means
"no brand": keep your site's own look.

| Field | Type | Meaning |
|---|---|---|
| `logo` | `BrandImage` | The site logo: PNG (keeps the upload's transparency), trimmed, at most 1200 px wide |
| `logoDark` | `BrandImage` | A logo for dark backgrounds. Null: show `logo` on a light plate instead |
| `icon32` | `String` | 32 × 32 PNG icon (favicon), absolute URL |
| `icon180` | `String` | 180 × 180 Apple touch icon, flattened on white, absolute URL |
| `icon192`, `icon512` | `String` | 192 × 192 and 512 × 512 PNG icons (for a web app manifest), absolute URLs |
| `accent` | `String` | The accent colour as lowercase `#rrggbb` |
| `fontPair` | `String` | The key of a curated display + body font pair. Null: keep your look's own fonts |

A `BrandImage` is `url` (absolute URL on the files host) plus the stored `width` and `height` in pixels. Pass them to
your `<img>` (or `next/image`) so the logo takes its space before it loads and the page does not shift. The four icons
are all set or all null: they come from one square upload.

`accent` is the owner's pick, not a tested colour. Do not paint text or buttons with it as is: derive the shades you
need from it against your own background, and check their contrast.

`fontPair` is currently one of `sport-condensed`, `clean`, `warm`, `classic`, `playful` or `streamer`: the curated
list (`FONT_PAIRS`) in the `@cmscraft/brand` package. The package also ships the font files and `fontPairCss(key)`,
which returns the CSS that switches a site to the pair. That CSS loads the files from `/fonts/…`, so copy
`node_modules/@cmscraft/brand/fonts/*` into your site's `public/fonts/`. Treat a key you do not know as null: the list
can grow, and a removed pair reads as no pair.

```json
{
  "data": {
    "publicProjectInfo": {
      "brand": {
        "logo": { "url": "https://files.example.com/projects/5/brand/3f1c….png", "width": 1200, "height": 340 },
        "logoDark": null,
        "icon32": "https://files.example.com/projects/5/brand/9a7e….png",
        "icon180": "https://files.example.com/projects/5/brand/b24d….png",
        "icon192": "https://files.example.com/projects/5/brand/0c55….png",
        "icon512": "https://files.example.com/projects/5/brand/e810….png",
        "accent": "#2f7d5b",
        "fontPair": "warm"
      }
    }
  }
}
```

Each new image gets a new URL, so you can cache the files for as long as you like. When the owner changes the logo,
the dark logo, the icon, the accent or the font pair, cms-craft sends the tags `project` and `project-<id>` to your site
([Cache revalidation](/guides/revalidation#tags)); tag your `publicProjectInfo` fetch with them.

The brand also holds the project's mail identity (mail logo, sender name, mail footer, company line). cms-craft uses
it in the e-mails it sends for the project; it is not in the public API.
