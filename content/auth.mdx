# Authentication

Every request to the public API names one cms-craft project with that project's **API token**, sent in the
`project-auth` header:

```http
POST /graphql/public HTTP/1.1
Host: main-craft.cms-craft.com
Content-Type: application/json
project-auth: <your project's API token>

{"query":"{ publicProjectInfo { name } }"}
```

Everything the API returns, and every form it accepts, belongs to the project the token identifies. There is no user
login, no cookie and no CSRF token on this endpoint.

## Getting the token

You request access yourself, in the admin panel; no e-mail is needed.

1. Sign up at the cms-craft admin and create a project. You are its owner.
2. Open the project, go to **Settings → Integrations** and find the **Request API access** card. Fill in **About your
   project** (its placeholder asks "What are you building? Who is it for?"; 10 to 1,000 characters) and press
   **Send request**. The card then shows **Request pending**.
3. cms-craft staff review the request. You get an e-mail when it is decided: approved, or not approved with an
   optional reason.

Only the project owner can send the request. A project has one pending request at a time. After a "not approved"
decision you can ask again 24 hours later, and one user can send at most 3 requests per 24 hours. A project whose site
cms-craft hosts cannot use the button: write to support@cms-craft.com. One account can own at most 3 projects in the
Build stage; a request that would make a fourth is refused.

After approval the project is a **developer project** that you own, in the Build stage (for development). In
**Settings → Integrations** two cards matter:

- **Developer** has what you need to make a request: the **Endpoint** (with a copy button), the **Header** name
  (`project-auth`), the project's **Stage** (Build, Live or Suspended), your **Usage**, and links to this
  documentation.
- **API Token** has the **Reveal token** button.

Both appear after your request is approved, and are shown only to the owner of the developer project and to cms-craft
staff. Other project members do not see them.

The token is 64 lowercase hexadecimal characters (`0-9`, `a-f`). Send it exactly as shown, with no prefix such as
`Bearer` and no spaces. Any other value is refused with `not matched token`.

### Usage

The **Usage** row shows how many requests (and, in the Build stage, mutations) the project made, counted per UTC day
and month. A Build project shows "N of 5,000 requests today", "N of 100 mutations today" and "N requests this
month". A Live developer project shows "N of 1,000,000 requests this month". The numbers and what they mean are in
[Errors & limits](/errors#usage). They are informational: nothing is refused during the beta.

Free during beta. Paid plans will follow; we will announce pricing and give notice before any charge.

## Regenerating the token

On the **API Token** card you can **Regenerate Token**. If cms-craft also hosts the project's site, you can reveal
the token but not regenerate it. E-mail support instead: we rotate it for you, so the hosted site keeps working.

The old token stops working **immediately**: every request that still sends it gets `not matched token`. The new
token can take up to 2 seconds to start working, so a request sent right after regenerating may also get
`not matched token`; retry it after a moment. Update the environment variable on every app that uses it right after
regenerating (and redeploy those apps if they read the variable at build time).

Regenerate the token if it leaked. Regenerating it does not change the [revalidation secret](/guides/revalidation).

A suspended project (Stage: Suspended) answers every request that carries its valid token with HTTP 403 and
`PROJECT_SUSPENDED`. Contact support@cms-craft.com to restore it.

## How secret is the token?

The token gives read access to the project's **published** content (which is public on the project's site anyway) and
lets its holder submit the project's public forms. It cannot read drafts, users or anything from the admin panel.
So it is not a disaster if it is exposed, but keep it out of browser code and public repositories anyway: someone who
has it can submit your forms (spam), read your published content through the API, and use up your token's
[rate limit](/errors#rate-limits).

Keep it in a server environment variable, as the [Quickstart](/getting-started) does.

## Call the API from your server

`/graphql/public` accepts requests from any origin: a browser on `localhost` or on your own domain works, and so do
server-side `fetch`, `curl` and build scripts. It never uses cookies: the API ignores any cookie the browser sends and
does not allow credentialed requests.

Still, call the API from your server: server components and SSR, route handlers or API routes, server actions, or at
build time. A token used in browser code is visible to every visitor of your site, who can then copy it.

For a form, post it to your own server (a route handler or server action) and call the mutation from there; see
[Form mutations](/guides/mutations).

## Introspection is off

Schema introspection is disabled in production; an introspection query fails with `GRAPHQL_VALIDATION_FAILED`. Use the
downloadable schema instead: [Schema & types](/schema).
