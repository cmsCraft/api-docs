# Errors & limits

## How errors arrive

The API follows the GraphQL convention: errors come back in an `errors` array, each with a `message` and an
`extensions.code`. Branch on `extensions.code` (and, for the cases below that say so, on the message), not on the
HTTP status.

- **The request was rejected before running** (a field that does not exist, a query that is too deep or too complex,
  malformed variables): HTTP **400**, and the body has no `data` key.
- **The request ran but a field failed** (missing token, module off, invalid form input…): HTTP **200**, `data` is
  `null` (or partial), and the error carries the `path` of the field that failed.
- **Two exceptions:** a [rate limit](#rate-limits) answers HTTP **429**, and a suspended project answers HTTP **403**.
  The body has the same shape as above.

## Error reference

| `extensions.code` | HTTP | When |
|---|---|---|
| `UNAUTHENTICATED` | 200 | `project-auth` is missing (`no token`), or is not a valid token or matches no project (`not matched token`). |
| `MODULE_DISABLED` | 200 | The operation belongs to a feature the project has not switched on. |
| `BAD_REQUEST` | 200 | Input failed validation (for example a page `limit` over 200, or an invalid contact form). |
| `NOT_FOUND` | 200 | The record you asked for does not exist or is not published. |
| `CONFLICT` | 200 | The request clashes with existing data, for example an address that is already subscribed. |
| `CONTACT_RECIPIENTS_NOT_CONFIGURED` | 200 | `sendContactRequest` on a project with no contact recipients set up. |
| `INTERNAL_SERVER_ERROR` | 200 | An unexpected error on our side. The message is `Internal server error`. |
| `TOO_MANY_REQUESTS` | 429 | You hit a [rate limit](#rate-limits). Wait for the seconds in `Retry-After`. |
| `PROJECT_SUSPENDED` | 403 | The token is valid, but the project is suspended. Retrying does not help: contact support@cms-craft.com. |
| `DAILY_LIMIT` | 429 | Reserved for a future hard daily limit. **Never returned today**: see [Usage](#usage). |
| `GRAPHQL_VALIDATION_FAILED` | 400 | Unknown field or argument, [depth limit](#query-limits), or an introspection query. |
| `BAD_USER_INPUT` | 400 | A variable is missing or has the wrong type. |
| `QUERY_TOO_COMPLEX` | 400 | The query is over the [complexity limit](#query-limits). |
| `BAD_REQUEST` | 405 | A mutation sent with `GET` (mutations need `POST`). |

### Shop errors

The [e-shop](/guides/shop) (beta) adds these codes. All of them answer HTTP **200**, and the ones with extra data put
it next to the code in `extensions`.

| `extensions.code` | HTTP | When |
|---|---|---|
| `SHOP_NOT_READY` | 200 | `createShopOrder` once the e-shop module is on but the owner has not finished setting the shop up. With the module off the code is `MODULE_DISABLED`. |
| `TERMS_NOT_ACCEPTED` | 200 | `termsAccepted` was not `true`. |
| `NOT_BUYABLE` | 200 | A product cannot be bought, or needs an option the line does not have. `extensions` has `productId` (and `optionId`). |
| `OUT_OF_STOCK` | 200 | Not enough stock. `extensions` has `productId` and `optionId`. Nothing is placed. |
| `INVALID_DELIVERY` | 200 | The delivery method, address, country or pickup point does not fit the order. |
| `PAYMENT_NOT_AVAILABLE` | 200 | The payment method is not offered by the shop, or `Cash` was used without a `Pickup` delivery. |
| `CARD_NOT_AVAILABLE` | 200 | `Card` was chosen. Card payments are not available yet. |
| `IDEMPOTENCY_KEY_REUSED` | 200 | The `idempotencyKey` was already used for an order with different content. |
| `RATE_LIMITED` | 200 | The e-mail already has 5 unpaid orders from the last 24 hours. Not the same as `TOO_MANY_REQUESTS`. |
| `NOT_FOUND` | 200 | `publicShopOrder` or `requestShopOrderWithdrawal` with an unknown, malformed or other project's token, or an order number and e-mail that do not match. |

A request with an invalid body (for example a malformed e-mail, or too many items) fails with `BAD_REQUEST`, as
described above.

### Examples

Missing token:

```json
{
  "errors": [
    {
      "message": "no token",
      "locations": [{ "line": 1, "column": 3 }],
      "path": ["publicProjectInfo"],
      "extensions": { "code": "UNAUTHENTICATED" }
    }
  ],
  "data": null
}
```

A wrong, malformed or regenerated token gives the same shape with `"message": "not matched token"`. So does a new
token in the first 2 seconds after you regenerate it ([Authentication](/auth#regenerating-the-token)).

Module not enabled:

```json
{
  "errors": [
    {
      "message": "Module \"ESHOP\" is not enabled for this project",
      "path": ["createShopOrder"],
      "extensions": { "code": "MODULE_DISABLED", "moduleType": "ESHOP" }
    }
  ],
  "data": null
}
```

Not found (for example `getPublicContentBySeoUrl` with an unknown URL):

```json
{
  "errors": [
    {
      "message": "Content not found",
      "path": ["getPublicContentBySeoUrl"],
      "extensions": { "code": "NOT_FOUND" }
    }
  ],
  "data": null
}
```

Unknown field:

```json
{
  "errors": [
    {
      "message": "Cannot query field \"usersFindAll\" on type \"Query\".",
      "locations": [{ "line": 1, "column": 3 }],
      "extensions": { "code": "GRAPHQL_VALIDATION_FAILED" }
    }
  ]
}
```

## Rate limits

Free during beta. Paid plans will follow; we will announce pricing and give notice before any charge.
We monitor usage during the beta, and limits may change with notice in the [changelog](/changelog). The
per-minute limits below are about bursts; the daily and monthly numbers are in [Usage](#usage).

Requests are counted **per operation** (each root field of a query counts on its own), over a **60-second window**.
The numbers below are the current defaults:

| Operations | Limit per minute |
|---|---|
| Most queries | 200 (per API token or per IP, see below) |
| `publicProducts`, `publicCategories`, `publicCategoryTree`, `getPublicPets`, `sitemapData`, `publicConnectionItems`, `publicConnectionSchedule` | 30 per IP |
| `createPublicBooking` | 20 per IP |
| `createShopOrder` | 20 per IP, and 20 for the whole project (per API token) |
| `requestShopOrderWithdrawal` | 5 per IP, and 20 for the whole project (per API token) |
| `sendContactRequest`, `subscribeNewsletter`, `unsubscribeNewsletter`, `submitRegistration`, `cancelRegistration`, `submitAdoptionRequest`, `publicOrderByNumber` | 5 per IP |
| `publicBookingByReference` | 5 per IP, and 60 per API token |

The 200-per-minute limit is counted per API token when the project is a developer project and cms-craft does not
host its site (the usual case if you build your own frontend). Otherwise it is counted per client IP address. The
other limits are always counted per IP.

When you go over, the response has HTTP **429**, a `Retry-After` header with the number of seconds to wait, and this
error:

```json
{
  "errors": [
    {
      "message": "Too many requests",
      "locations": [{ "line": 1, "column": 12 }],
      "path": ["cancelRegistration"],
      "extensions": { "code": "TOO_MANY_REQUESTS" }
    }
  ],
  "data": null
}
```

Every response carries the counters as headers: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`
(seconds), plus a suffixed set for the operation's group, for example `X-RateLimit-Limit-read`.

What this means in practice:

- **Your server is one IP.** When your site calls the API from its server, every visitor shares that server's
  per-IP limits. A contact form handled by your server allows 5 submissions per minute for the whole site; cache
  reads (the [Quickstart](/getting-started) caches every query until the content changes) instead of querying per
  visit.
- **Builds count too.** A static build that renders hundreds of pages one query each can hit the 200-per-minute
  limit. Prefer list queries over one query per page, limit build concurrency, and retry after `Retry-After`.

## Usage

Every operation that carries a valid token is counted for your project, once per request: a query with five root
fields or aliases counts once, while the per-minute rate limits count each root field. Counting is separate from the per-minute [rate limits](#rate-limits) above. Each
request counts when it is answered, including one that comes back with an error such as `NOT_FOUND`; a request
for a suspended project, or with a missing or wrong token, is not counted.

| Project | Counted and limited |
|---|---|
| Any project in the **Build** stage | 5,000 requests and 100 mutations per day |
| Developer project that is **Live** | 1,000,000 requests per month |
| Any other project (a Live project that is not a developer project) | Counted, no limit |

Days and months follow UTC. A mutation counts toward both the request total and the mutation total.

**Nothing is refused during the beta.** If a project goes over a limit, we get a notice and may contact you, but
your requests keep working. Should we ever start refusing requests over a limit, it will be announced in the
[changelog](/changelog) first, and the answer will be HTTP 429 (`DAILY_LIMIT`).

You see your own numbers (requests and mutations today, requests this month) in the Developer panel of the admin
panel: [Authentication](/auth#getting-the-token).

## Query limits

- **Depth:** at most **10** levels of nesting. Deeper queries fail with `GRAPHQL_VALIDATION_FAILED`:
  `'MyQuery' exceeds maximum operation depth of 10`.
- **Complexity:** at most **1000** points per request. Every selected field costs 1 point, and some list queries
  (such as `publicProducts`, `publicCategories`, `sitemapData`) add a fixed 10 to 50. Over that, `QUERY_TOO_COMPLEX`:
  `Query complexity 1200 exceeds maximum allowed complexity 1000`. Ask only for the fields you render.
- **Introspection** is disabled; use the [downloadable schema](/schema).
